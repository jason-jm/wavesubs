# 字幕质量基准

用影片自带的官方字幕作为 ground truth，量化评估生成结果。改动识别或时间轴逻辑后**务必跑一遍**，
用数据确认是改进而不是回归——项目历史上出现过多次「看起来更合理、实际更差」的改动。

## 用法

```bash
# 1. 从影片里抽出音频与官方字幕（一次 ffmpeg 读取同时产出，避免重复读大文件）
ffmpeg -i movie.mkv -map 0:a:0 -ac 1 -ar 16000 -c:a pcm_s16le movie.wav \
                    -map 0:s:1 -f srt movie.gt.srt

# 2. 用当前管线生成字幕
npm run cli -- movie.wav --language en --model ggml-large-v3-turbo.bin --out-dir ./out

# 3. 对比
python3 bench/evaluate.py "片名" movie.gt.srt out/movie.en.srt
```

可以一次传多组 `名称 GT 生成` 做批量对比。

## 指标怎么读

| 指标 | 含义 | 参考值 |
|---|---|---|
| 词错率 WER | 与官方字幕的文本差异 | 英语片 15~25% 属正常。官方字幕会做口语压缩、省略语气词，**永远不可能到 0** |
| 语音覆盖率 | 官方字幕显示时间里我们也出字幕的比例 | 75~85%。官方字幕含歌词、音效描述，这部分我们本来就不该有 |
| 漏掉的 GT 条目 | 完全没有对应字幕的官方条目 | 7~10%，但其中绝大多数是歌词与非语音，真正漏掉的对白通常 <0.5% |
| 句首偏差 | 一段话第一句的出现时刻误差（正=晚，负=早） | 中位应接近 0，±0.5s 内占比越高越好 |
| 结构问题 | 重复条目、超 15s 长条、>60s 空洞 | 重复必须为 0；长条越少越好；空洞要逐个核对是不是真无对白 |

跨语种（如日语音轨 vs 英文字幕）时 WER 无意义，只看时间轴与结构指标。

## 翻译质量不能用 WER/CER 衡量

实测过：同一段日语用 8B、8B+改进提示词、32B 三种方式译成中文，与官方中文字幕的字错率分别是
78.1% / 78.2% / 80.1%——几乎不动，而且质量最好的 32B 反而"最差"。原因是两份独立的优秀翻译
本来就用词迥异，字面距离衡量不了达意程度。

评翻译质量要看这些：

- **未译净残留**：译文里出现目标语言不该有的文字（中文译文里的假名、英文译文里的汉字）
- **平均字数比**：与官方字幕相比过短说明信息丢失
- **漏译条数**
- **逐条人工抽样**：重点看惯用语、双关、以及同一个词在不同场景的歧义（如日语「入れ」既是"倒"也是"进来"）
